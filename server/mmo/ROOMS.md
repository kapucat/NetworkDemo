# MMOの部屋機能

ログイン後に部屋を作成・選択し、同じ部屋のプレイヤーと移動・チャットを共有します。

## 操作

1. 別々のアカウントでログインします。
2. 1人が部屋名を入力して「部屋を作成」を押します。
3. もう1人が一覧から同じ部屋に参加します。
4. 各自が「準備完了」を押すと、3秒のカウントダウン後に移動できます。
5. プレイ中は上部の「部屋から退出」で一覧に戻れます。

1部屋は最大4人、開始には2人以上必要です。同じアカウントは同時に複数の接続で部屋に参加できません。
開始前に参加者が抜けるとカウントダウンを取り消し、残った人の準備状態を解除します。
準備完了の取り消しでもカウントダウンを中止できます。
開始後に誰かが抜けても、残ったメンバーはプレイを続けられます。
開始準備中・プレイ中の部屋には新規参加できません。

## 通信と状態管理

新しいクライアントは`/ws?token=...&rooms=1`で接続します。
部屋への参加・準備状態・開始時刻はGoのHubが一か所で管理します。
`waiting → countdown → playing`の状態遷移をサーバーで決定し、開始前の移動データを受け付けません。
クライアントは往復通信からサーバー時刻との差を見積もってカウントダウンを表示し、サーバーの開始通知後に操作を解放します。

| メッセージ | 用途 |
|---|---|
| `room.list` | 部屋一覧の取得・通知 |
| `room.create` / `room.join` / `room.leave` | 作成・参加・退出 |
| `room.ready` | 準備状態の変更 |
| `room.state` / `room.left` / `room.error` | 状態・退出結果・エラーの通知 |
| `room.ping` / `room.pong` | サーバー時刻との差の推定 |
| `player.move` / `chat` | `room_id`を付けて同じ部屋だけに配信 |

送信者のアカウントID・名前は認証済み接続から決定します。
部屋切替時にはクライアントの他プレイヤー表示とチャット履歴を消し、遅れて届いた別の部屋の移動・チャットは破棄します。
通信断後の再接続では一覧へ戻り、部屋を選び直します。管理者切断では従来どおりログイン画面へ戻ります。
部屋情報はメモリ上で管理し、空室は削除します。サーバー再起動で部屋は初期化されます。

## 旧クライアント

`rooms=1`を付けないクライアントは、従来の共通フィールドを利用できます。
新しい部屋との間でプレイヤー情報・チャット・移動は共有しません。

## 検証

`go test ./...`で状態遷移、人数制限、同一アカウントの重複参加、開始前移動拒否、部屋の分離、実WebSocketでの通信を確認します。
DockerビルドではLinux上で`go test -race ./...`と`go vet ./...`も実行します。
`rooms_live_test.go`は明示指定時だけ公開環境へ接続する試験です。通常のテストでは実行しません。
実際のUnity画面での操作・別PC間の見た目は、ビルドを起動して別途確認します。

## 管理ツールの部屋一覧

管理ツールの「MMO部屋一覧」では、部屋名・人数・準備完了人数・進行状態と、参加者ごとの名前・アカウントID・準備状態を確認できます。
部屋名・部屋ID・参加者名で検索し、「再読込み」で更新します。
サーバーの`--admin-rooms`コマンドは、Hubがコピーした取得時点の情報を返します。部屋の変更操作や認証情報は含みません。
