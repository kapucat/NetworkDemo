# MMO監視版サーバー

公開サーバーのソースを基準に、admin_monitor.goとreadPumpへの監視フックを追加したビルド元。
監視はDBを変更しない。接続終了の監査用スキーマは002_admin_kicks.sqlで別途作成し、アカウント・セッション・ランキングは変更しない。

監視用の状態は独立したミューテックスで保護する。移動検証用のフィールドを別ゴルーチンから参照しない。
readPump開始・終了、検証済み移動、受理済みチャット、受信・Pongで更新する。
接続IDはサーバープロセス内の連番。同じアカウントの複数接続を保持する。
パスワード・ハッシュ・トークン・接続元IPを監視データに含めない。

監視HTTPはコンテナ内の127.0.0.1:8091だけで待ち受け、公開HTTPのMuxに登録しない。
SSH経由の固定コマンド `docker exec hookrunner-exhibition-api-1 /server --admin-snapshot` で読む。
コマンドはDB初期化やWebSocketサーバー起動を行わず、内部の監視HTTPから取得して終了する。
チャットは1接続50件までで切断時に破棄。履歴の永続保存やオフラインアカウントの一覧は未対応。

配備はリポジトリの `scripts/DeployMmoMonitor.ps1` を使う。
Dockerビルド内でgo test -race、go test、go vetを行ってから本体をビルドする。
接続があれば更新を中止する。旧イメージをタグで保管し、起動確認に失敗したら戻す。
公開ゲートウェイはAPI更新後に設定を再読込みする。
元の~/HookRunnerMMO/serverのファイルは変更しない。今後の監視版更新も本リポジトリのビルド元と配備スクリプトを使用する。

## 接続終了

`--admin-kick` と `--admin-kick-status` はJSONを標準入力で受け、コンテナ内の固定HTTPへPOSTする。
要求はVersion、OperationID（UUID）、ServerID（起動ごとのランダムID）、AccountID、ConnectionIDs、Reason。
監査用のDBへの保存が確認できてから、同じ起動ID・アカウント・接続IDの対象ソケットだけを閉じる。
対象が1件でも変わっていれば全件を中止する。DBへの保存中は監視状態のミューテックスを保持しない。
同じ操作IDは再実行せず、保存済みの結果を返す。要求内容が異なる再送は拒否する。

切断とDB更新は単一のDBトランザクションにはできないため、先にStartedを永続保存する。
結果保存に失敗した場合、照会で対象の古い接続がなくなっていればTargetsGoneと記録する。
これは管理操作が切断の原因だったことを断定する状態ではない。残っていればStartedのままで、勝手に切断を再実行しない。
サーバー再起動後もDBの操作IDを使って照会でき、再利用された接続IDへ切断要求を流用しない。

管理者切断は1008（PolicyViolation）のCloseフレームで通知してからソケットを閉じる。
対応するUnityクライアントは自動再接続を止め、ローカルのログイン情報を消してLoginSceneへ戻る。通常の通信断の自動再接続とは分ける。
古いゲームビルドにはこの動作がないため、クライアントの更新・再ビルドも必要。

配備スクリプトはテスト後、接続者ゼロを確認して監査スキーマを作成し、APIを更新する。
`003_admin_accounts.sql` は登録アカウント削除の計画・削除前データ・結果を保持する。管理要求は `--admin-accounts` から内部 `/accounts` へ転送し、公開APIには登録しない。
`list / prepare / execute / lookup / cancel` に対応する。削除対象は固定したaccount_idの1件と従属セッションで、ランキングには書き込まない。
確認後に登録情報やセッションが変わった場合、接続中、10分の期限切れでは中止する。
ログインとWS受付は `accountAdmission` の読取りロックを使い、削除は書込みロックで競合を防ぐ。認証直後のWSは監視登録を済ませてからロックを解放する。
DBでは対象照合と削除・完了記録を同じ取引で確定する。認証情報を含む元行はDB監査表の中だけに保持し、管理応答は公開用のアカウント項目のみを返す。
`scripts/TestMmoAccountsRemote.ps1` は専用の使い捨てDBで削除・競合・ロールバックを検証し、既存DBは使わない。
Windows側の `--live-mmo-kick-safe` テストは、存在しないアカウント・接続IDを使って要求と結果照会を検証する。
本番DBには対象なしの監査レコードが1件残るが、実プレイヤーの切断は行わない。
